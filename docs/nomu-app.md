# 何飲む？（メニュー写真 → 注文集計）

居酒屋のテーブルで「結局、何を何杯頼むんだっけ？」を解決するミニアプリです。
メニュー写真を撮ると品目を読み取り、メンバーごとの注文を積み上げて、
**店員さんにそのまま読み上げられる形**に集計します。

- URL: `/nomu`（ログイン不要）
- 会員システム側の DB（Prisma）には一切書き込みません

## 使い方

1. **メニュー** タブで「写真を撮る」または「画像を選ぶ」
   → AI がメニューを読み取り、品名・価格・カテゴリの一覧になります
   → 読み取りミスはその場で修正、載っていない品は「追加」で手入力できます
   → 続けて別のページを撮ると、品名が重複しないものだけ追記されます
2. **注文** タブでメンバーを追加し、名前を選んでから飲みたいものを ± でカウント
   → 決められない人には「迷ったらおまかせ」（ノンアル限定も可）
3. **集計** タブで
   - 品目 × 合計杯数（多い順）と誰が頼んだか
   - 合計金額 / 共有用テキストのコピー・共有（Web Share API）
   - 支払い: 飲んだ分だけ（実費）と 100 円単位の割り勘

### 2回目以降の注文（おかわり）

店員さんに伝えたら「この注文を伝えた（発注済みにする）」を押します。
以降は **今回頼む分（＝現在の注文 − 発注済み）** だけが上に出るので、
2 杯目・3 杯目を頼むときに何が追加なのかがひと目で分かります。
支払い欄と「これまでの合計」は、その日の累計で計算されます。

入力内容は端末の `localStorage`（キー: `nomu-app-state-v1`）に保存されるので、
リロードしても消えません。ヘッダー右上の ↺ で全消去できます。
※ 写真自体は容量が大きいため保存対象外（リロードでプレビューだけ消えます）。

## 構成

| ファイル | 役割 |
| --- | --- |
| `app/nomu/page.tsx` | 画面全体の状態管理・タブ・localStorage 永続化 |
| `components/nomu/menu-scanner.tsx` | 写真撮影/選択、縮小、読み取り、品目の編集 |
| `components/nomu/order-board.tsx` | メンバー管理と 1 人ずつの注文入力 |
| `components/nomu/order-summary.tsx` | 集計表示、共有テキスト、支払い |
| `lib/nomu.ts` | 集計・差分（今回頼む分）・共有テキスト生成・割り勘などの純粋関数 |
| `lib/nomu-vision.ts` | メニュー写真の読み取り（OpenAI Vision） |
| `app/api/nomu/scan/route.ts` | 読み取り API（`POST /api/nomu/scan`） |

## 環境変数

| 変数 | 説明 |
| --- | --- |
| `OPENAI_API_KEY` | 未設定ならサンプルメニューを返す（画面上に注意書きを表示） |
| `AI_VISION_MODEL` | 読み取りに使うモデル。デフォルト `gpt-4o-mini` |

API キーが設定されている状態で読み取りに失敗した場合は、
サンプルに差し替えず**エラーを返します**（読めていないのに
それらしいメニューが出ると誤発注につながるため）。

## API

```
POST /api/nomu/scan
{ "image": "data:image/jpeg;base64,..." }

200 → { "items": [{ "name": "生ビール（中）", "price": 580, "category": "ビール" }], "isMock": false }
400 → 画像が未指定 / 形式不正
413 → 画像が大きすぎる（縮小後 4,000,000 文字超）
502 → 読み取り失敗（AI 側のエラー）
```

画像はクライアント側で長辺 1600px の JPEG に縮小してから送信します。
サーバー側では保存せず、その場で読み取って破棄します。

## 集計ロジックのテスト

`lib/nomu.ts` は外部依存のない純粋関数なので、`lib/nomu.test.ts` で検証できます。

```bash
npm run test:nomu
```

## 拡張のアイデア

- 複数端末で同じ注文を共有する（ルーム ID + DB or Vercel KV）
- 「前回と同じ」注文の呼び出し（履歴の保存）
- 飲み放題モード（金額計算を非表示にして杯数のみ集計）
